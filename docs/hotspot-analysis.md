# 命題熱點分析邏輯

## 目前狀態

首頁「熱點排行原型」目前是展示用資料，來源是 `lib/hotspots.ts` 的手動假資料。

這些數字用來確認產品呈現方式，例如排行、趨勢、常見考法與練題入口；尚未代表真實命題統計。

目前已完成的是「行政法官方試題索引」串接：

- 來源：考選部國家考試試題索引開放資料
- 檔案：`lib/moex-admin-law-data.json`
- 內容：年度、考試、類科、科目、題型、試題連結、答案連結
- 限制：這份資料只有「試卷索引」，沒有逐題文字與章節標籤

## 正式版分析流程

正式的命題熱點不應該靠人工猜，也不應該每次使用者開頁面才即時計算。建議流程如下：

1. 抓取官方索引
   從 MCP 或考選部開放資料取得試題索引，保留原始快照。

2. 正規化資料
   將年度、考試名稱、類科、科目、題型、試題網址整理成穩定格式。

3. 下載試題 PDF
   依照索引中的試題網址下載行政法試題。

4. 解析題目文字
   將 PDF 轉成逐題文字；若 PDF 是掃描圖，需加 OCR。

5. 題目切分
   將一份試卷拆成第 1 題、第 2 題等題目單位，並保留題型與年度。

6. 考點標記
   用「規則 + AI」判斷每題屬於哪些章節與考法，例如行政處分、行政罰、訴願、行政訴訟、國家賠償。

7. 人工抽查
   對高頻考點與低信心標記做人工校正，避免 AI 把相近章節混在一起。

8. 產生統計表
   依年度、考試、類科、科目、題型彙整出排行、趨勢、常見考法與建議練習。

9. 前端讀取分析結果
   網站只讀已經整理好的 JSON 或資料庫結果，不在頁面即時計算。

## 熱點分數建議

先用簡單可解釋的規則，不急著做黑盒分數。

```text
熱點分數 =
近三年出題次數
+ 最近一年出題次數 x 0.5
+ 申論題次數 x 0.4
+ 跨考試類科出現次數 x 0.3
```

分數只用來排序。畫面上仍應顯示原始出題次數，讓使用者知道熱點不是憑空產生。

## 產品呈現原則

- 對學生顯示「高頻章節、常見考法、近年趨勢、可練歷屆題」。
- 對內部管理者顯示「資料來源、解析狀態、低信心題目、人工校正入口」。
- 凡是尚未由 PDF 解析驗證的資料，都標成原型或待驗證。
